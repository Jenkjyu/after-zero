# AI 识图录入债务：实施交接计划

状态：首版客户端、服务端额度与云函数已实现并部署，**等待真实截图与 iPhone 验收**。本文件记录 2026-08-21 的范围、实现结果和剩余门槛。

## 产品目标

将现有“AI 债务分析聊天”迁移为“AI 识图录入债务”。用户上传同一笔债务的多张还款计划截图，系统一次性识别整组图片，生成一份可编辑的手动债务草稿；用户补齐信息并确认后，才真正新增债务。

Premium 为一次性购买 ¥28。正式购买包含 25 次终身 AI 识图录入额度；7 天 Premium 体验另含 3 次 AI 识图录入额度，体验额度与买断额度独立计算，不把买断的 25 次额度发给体验用户。

## 不可变的产品规则

1. 一组图片只对应一笔债务；用户可连续添加 1 至 N 张，同组图片不在上传时自动识别。
2. 仅用户点击“开始识别”后处理整组图片。成功产出一份有效草稿才扣 1 次；三张连续截图仍只算 1 次。
3. 识别失败、图片不可读或未生成有效草稿，不扣次数；同一任务的网络重试必须幂等，不得重复调用或扣费。
4. 用户取消草稿不新增债务，但成功识别的额度不退，因为服务已经发生。
5. 不向用户索取年化利率或还款方式。草稿必须落到既有“手动添加”债务表单与 `plan` 账本，派生字段继续由 `recompute()` 计算。
6. 截图中的“已入账 / 待入账”只作来源提示，绝不自动映射为 `PlanRow.paid`。
7. 截图中的贴息金额不自动扣减利息；以“识别备注”预填进债务 `notes`，由用户确认或删除。
8. 图片仅作本次识别的临时文件，不进入用户档案、云备份或长期图片库；识别完成后删除，失败任务由定时清理兜底。

## 用户交互

### 入口与门禁

- 债务页 AI 入口改为“AI 识图录入”。
- 非 Premium 用户跳转 Premium 页面，并说明“买断含 25 次 AI 识图录入”。
- 已开通但未登录时，复用 `requestCloudLogin()`，明确告知图片只用于生成草稿、债务不会自动同步。
- 旧聊天 AI 的“50 次/月”“复制到外部 AI”入口不复用为新额度。新功能完成并验收后，再进行一次性切换与下线。

### 上传页

使用全屏 `subpage`，顶部固定三步：`上传截图 → 识别草稿 → 补齐并确认`。

- 支持相册/文件添加，显示缩略图、上传顺序、删除与重排。
- 页面明确写“请只上传同一笔债务的还款计划”。
- 至少一张图后才启用主按钮：`开始识别 · 成功后消耗 1 次`。
- 旁注固定说明“失败不扣次数；同组多张图片仅算 1 次”。
- 处理中锁定图片集，显示上传、识别、合并重复期数、生成草稿四个阶段；退出后再次打开需能恢复该任务状态。

### 草稿确认

识别成功后先展示简短结果说明，再进入现有 `EditSheet` 的“AI 草稿模式”，而不是新建第二套债务编辑器。

- 自动填入逐期日期、本金、利息、金额；金额固定按本金加利息生成。
- 用户必须填写贷款产品与借款日；出资方、类型、备注保持可选。
- 逐期表格继续复用 `PlanRows`，允许用户修改、删除、补充期次。
- 顶部黄色提示固定为“请在下方核对并补齐识别草稿，确认无误后再新增债务。”，不展示模型 warnings 或 OCR 处理细节。
- 保存按钮在草稿模式显示“确认新增债务”。只有它调用既有 `setDebt(null, obj) → saveAll() → renderAll()`。
- 离开草稿时提示“不会新增债务；已完成的识别额度不会退回”。

## 服务端方案

### 任务与临时图片

新增 AI 识图任务能力，不修改现有文本聊天 `aiAdvisor` 的月度 `aiUsage` 语义。

建议新增：

- `aiImportSessions`：`userId`、状态、图片 ID、草稿、是否扣费、过期时间、幂等键。
- `aiImportCredits`：`userId`、权益归属、`limit`、`used`、预留次数、更新时间。
- CloudBase 临时 Storage 路径：按随机 session ID 隔离，只允许任务所属身份读取。

流程：客户端上传临时图片文件 ID → 服务端锁定 session 并预留额度 → OCR 读取全部图片 → 文本模型把 OCR 结果合并为固定 JSON → 服务端校验 → 成功时预留转已用并返回草稿；任何失败释放预留。

预留机制用于防止连续点击或并发任务在最后一条额度上重复发起高成本调用。成功任务再次请求必须直接返回原草稿，不得再次计费。

### 识别与草稿校验

第一版采用腾讯云 `GeneralBasicOCR` 对每张截图提取文字，再用 CloudBase `hy3` 将全部 OCR 文本合并为固定 JSON。OCR 使用云函数运行时临时凭据，不在代码或部署配置中保存长期密钥；文本模型可通过 `AI_IMPORT_TEXT_MODEL` 替换。每张截图会产生一次 OCR 调用，但用户的一组同债务截图在成功生成草稿时仍只消耗 1 次产品额度。当前账号的 OCR 权限、实际识别率和成本仍需用约 20 组脱敏真实截图验证。

服务端草稿至少包含：期数、计划日期、本金、利息、金额、来源状态文字和通用 `reviewItems`。模型只把可能影响金额、日期、费用或还款状态的原图业务信息放入 `reviewItems`，保留原文和期数/上下文；贴息、服务费、减免等新词不依赖固定词表。服务端 `normalizeDraft` 过滤 OCR 清洗、重复合并、置信度等内部噪音，将业务相关项目统一写成简短备注供用户核对；贴息类备注明确写“系统未自动抵扣”，但从不自动标记已还。服务端必须验证日期、非负金额、`金额 = 本金 + 利息`、至少一条有效计划行，并按期数/日期合并重叠截图。

## 验收与发布门槛

1. 三张同一笔债务的连续截图只生成一份草稿、只扣 1 次。
2. 重叠截图不生成重复期次；贴息只进入备注；“已入账”不勾选已还。
3. 用户取消草稿、网络重试、页面重进均不创建债务或重复扣费。
4. 最终确认前，本地债务、提醒、统计均无变化；确认后数据进入既有账本并正常参与提醒/统计。
5. 覆盖未登录、登录取消、非 Premium、体验、已购买、额度耗尽、失败、低置信度、并发和恢复购买。
6. 在真实 iPhone 上验证图片选择、上传、深浅主题、长表格滚动、返回链及敏感图片删除。

## 当前实现结果（2026-08-21）

- 债务页入口已切换为“AI 识图录入”；旧聊天助手代码和数据键保留，但首页不再进入旧页面。
- 新增 `AiImportScreen`：支持 1–20 张图片、缩略图、排序、删除、上传/识别状态和失败重试；同组共享幂等任务标识。
- 识别成功后复用 `EditSheet`：预填产品提示、出资方、类型、备注和逐期计划；借款日留空；所有 `paid` 强制为 `false`；只有“确认新增债务”调用原有 `setDebt(null, obj) → saveAll() → renderAll()`。
- 新增并部署 `aiDebtImport`；创建 `aiImportSessions`、`aiImportCredits` 两个 `ADMINONLY` 集合。成功草稿才计费，买断额度固定 25，多图计 1 次；失败释放预留；并发/网络重试通过任务租约与幂等结果避免重复扣费。
- 账户合并会合并识图用量并封顶 25；注销会删除识图草稿并保留恢复已购权益所必需的已用次数，防止通过注销重置终身额度。相关 `accountBinding`、`deleteAccount`、`premiumEntitlement` 已部署。
- App 内 Premium 文案、会员协议、用户协议、隐私政策及公开站点源码已同步识图处理、体验 3 次与买断 25 次额度和临时图片/24 小时草稿期限。
- TestFlight `1.0.0 (6)` 首次实测发现客户端漏随包引入 CloudBase Storage 模块，导致图片上传在调用 OCR 前报 `uploadFile is not a function`，没有上传图片、调用 OCR 或消耗额度。现已补入与核心 SDK 同为 `2.28.6` 的 `cloudbase.storage.js`，并新增静态回归检查；修复版 `1.0.0 (7)` 已成功上传 App Store Connect，等待 Apple 处理后在 TestFlight 复测。
- `1.0.0 (7)` 进一步实测发现 CloudBase 存储桶原为“仅管理员可读写”，已在控制台切换为“仅创建者及管理员可读写”；云端操作成功，不需重新发版，待权限传播后复测截图上传。
- `1.0.0 (7)` 权限修复后仍出现空的 Storage 操作错误，现已将 AI 临时图片改为登录态 `aiDebtImport` 云函数代理上传：客户端压缩图片后调用 `callFunction`，服务端校验任务归属并用管理员 SDK 写入 `ai-import/<sessionId>/...`，失败由服务端清理；既有云备份上传路径不变。
- 云函数已重新部署；失败任务可重试且会清空临时文件，不扣额度。客户端回归测试、Node/React/TypeScript、iOS sync 和 `git diff --check` 均通过；构建 `1.0.0 (8)` 已成功上传 App Store Connect，当前等待 Apple 处理。
- TestFlight `1.0.0 (8)` 实测确认上传成功但 OCR 第 1 张失败；云函数已从“临时 URL 直传 OCR”改为 `downloadFile` 读取 Buffer 后使用 `ImageBase64` 调腾讯云 `GeneralBasicOCR`。用户随后已在同一腾讯云主账号自行开通文字识别服务，但原提示仍存在。
- 临时云端自检取得实际错误 `AuthFailure.UnauthorizedOperation`：CloudBase 默认运行角色 `TCB_QcsRole` 缺少 `ocr:GeneralBasicOCR`。现已创建只含该 action 的 `AfterZeroAiDebtImportOcr` 自定义策略，并关联到 `TCB_QcsRole`；关联后同一自检确认数据库可访问，OCR 请求已通过鉴权进入图片解码阶段。曾尝试切换为 OCR 专用角色，但会失去 `tcb:QueryDocument`，已立即显式恢复默认角色，期间未写入业务数据。
- 最终 `aiDebtImport` 已重新部署，部署配置显式固定 `role: TCB_QcsRole`；临时诊断入口已删除，并新增未授权、服务未开通、图片格式异常的明确错误映射。现有 TestFlight `1.0.0 (8)` 无需重新发版，待真实截图复测 OCR → `hy3` → 可编辑草稿完整链路。
