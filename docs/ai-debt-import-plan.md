# AI 识图录入债务：实施交接计划

状态：已确认产品方向，**尚未开始实现**。本文件记录 2026-08-21 的范围、交互和实现边界；开始编码前应再次核对当前 `AGENTS.md`、相关 skill 与本文件。

## 产品目标

将现有“AI 债务分析聊天”迁移为“AI 识图录入债务”。用户上传同一笔债务的多张还款计划截图，系统一次性识别整组图片，生成一份可编辑的手动债务草稿；用户补齐信息并确认后，才真正新增债务。

Premium 为一次性购买 ¥28。正式购买包含 25 次终身 AI 识图录入额度；建议既有 7 天 Premium 体验只提供 1 次体验额度，避免体验期消耗完整 25 次。此建议在实现前需由产品负责人最终确认。

## 不可变的产品规则

1. 一组图片只对应一笔债务；用户可连续添加 1 至 N 张，同组图片不在上传时自动识别。
2. 仅用户点击“开始识别”后处理整组图片。成功产出一份有效草稿才扣 1 次；三张连续截图仍只算 1 次。
3. 识别失败、图片不可读或未生成有效草稿，不扣次数；同一任务的网络重试必须幂等，不得重复调用或扣费。
4. 用户取消草稿不新增债务，但成功识别的额度不退，因为服务已经发生。
5. 不向用户索取年化利率或还款方式。草稿必须落到既有“手动添加”债务表单与 `plan` 账本，派生字段继续由 `recompute()` 计算。
6. 截图中的“已入账 / 待入账”只作来源提示，绝不自动映射为 `PlanRow.paid`。
7. 截图中的贴息金额不自动扣减利息；以“识别备注”预填进债务 `notes`，由用户确认或删除。
8. 图片仅作本次识别的临时文件，不进入用户档案、云备份或长期图片库；识别完成后删除，失败任务由定时清理兜底。

## 用户交互

### 入口与门禁

- 债务页 AI 入口改为“AI 识图录入”。
- 非 Premium 用户跳转 Premium 页面，并说明“买断含 25 次 AI 识图录入”。
- 已开通但未登录时，复用 `requestCloudLogin()`，明确告知图片只用于生成草稿、债务不会自动同步。
- 旧聊天 AI 的“50 次/月”“复制到外部 AI”入口不复用为新额度。新功能完成并验收后，再进行一次性切换与下线。

### 上传页

使用全屏 `subpage`，顶部固定三步：`上传截图 → 识别草稿 → 补齐并确认`。

- 支持相册/文件添加，显示缩略图、上传顺序、删除与重排。
- 页面明确写“请只上传同一笔债务的还款计划”。
- 至少一张图后才启用主按钮：`开始识别 · 成功后消耗 1 次`。
- 旁注固定说明“失败不扣次数；同组多张图片仅算 1 次”。
- 处理中锁定图片集，显示上传、识别、合并重复期数、生成草稿四个阶段；退出后再次打开需能恢复该任务状态。

### 草稿确认

识别成功后先展示简短结果说明，再进入现有 `EditSheet` 的“AI 草稿模式”，而不是新建第二套债务编辑器。

- 自动填入逐期日期、本金、利息、金额；金额固定按本金加利息生成。
- 用户必须填写贷款产品与借款日；出资方、类型、备注保持可选。
- 逐期表格继续复用 `PlanRows`，允许用户修改、删除、补充期次。
- 顶部黄色提示说明：入账日暂按计划还款日导入；状态不等于已还；贴息未自动抵扣利息。
- 保存按钮在草稿模式显示“确认新增债务”。只有它调用既有 `setDebt(null, obj) → saveAll() → renderAll()`。
- 离开草稿时提示“不会新增债务；已完成的识别额度不会退回”。

## 服务端方案

### 任务与临时图片

新增 AI 识图任务能力，不修改现有文本聊天 `aiAdvisor` 的月度 `aiUsage` 语义。

建议新增：

- `aiImportSessions`：`userId`、状态、图片 ID、草稿、是否扣费、过期时间、幂等键。
- `aiImportCredits`：`userId`、权益归属、`limit`、`used`、预留次数、更新时间。
- CloudBase 临时 Storage 路径：按随机 session ID 隔离，只允许任务所属身份读取。

流程：客户端上传临时图片文件 ID → 服务端锁定 session 并预留额度 → OCR 读取全部图片 → 文本模型把 OCR 结果合并为固定 JSON → 服务端校验 → 成功时预留转已用并返回草稿；任何失败释放预留。

预留机制用于防止连续点击或并发任务在最后一条额度上重复发起高成本调用。成功任务再次请求必须直接返回原草稿，不得再次计费。

### 识别与草稿校验

第一版采用“OCR 提字 + 文本 AI 整理”，而非假定当前 `hy3` 文本模型可直接读取图片。先以约 20 组脱敏真实截图验证识别率、合并质量和成本；复杂样式的视觉模型仅作为后续兜底。

服务端草稿至少包含：期数、计划日期、本金、利息、金额、来源状态文字、贴息说明、低置信度/重复项警告。服务端必须验证日期、非负金额、`金额 = 本金 + 利息`、至少一条有效计划行，并按期数/日期合并重叠截图。

## 验收与发布门槛

1. 三张同一笔债务的连续截图只生成一份草稿、只扣 1 次。
2. 重叠截图不生成重复期次；贴息只进入备注；“已入账”不勾选已还。
3. 用户取消草稿、网络重试、页面重进均不创建债务或重复扣费。
4. 最终确认前，本地债务、提醒、统计均无变化；确认后数据进入既有账本并正常参与提醒/统计。
5. 覆盖未登录、登录取消、非 Premium、体验、已购买、额度耗尽、失败、低置信度、并发和恢复购买。
6. 在真实 iPhone 上验证图片选择、上传、深浅主题、长表格滚动、返回链及敏感图片删除。
