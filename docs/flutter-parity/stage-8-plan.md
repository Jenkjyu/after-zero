## 总验收原则

- 唯一基准是旧版源码加旧版实际运行表现，文档只提供线索。
- 不用“像素差低于 3%”之类阈值宣布通过。目标是零个未解释差异。
- 字体抗锯齿、平台系统界面等不可避免差异，也必须提供证据并由用户明确接受；agent 不能自行认定为“合理改进”。
- 每个业务阶段同时完成 UI、排版、文案、交互、手势、数据结果、错误状态、明暗主题及持久化，不把视觉或真机验证留成尾巴。
- 旧版目录继续只读，所有实现、测试和工具只写入 Flutter、测试、CI 和审计文档范围。

## 阶段 8.1：权威基准与完整性证明系统

完整交付一套可重复运行的全量对齐体系，本阶段不急着修产品界面。

工作范围：

- 从 `www/index.html`、`react/src/**`、bridge API、本地存储键、云函数、原生插件和旧版实际运行中，重新枚举所有入口、状态、操作和副作用。
- 建立机器可检查的 parity matrix，每项记录旧版源码位置、Flutter 对应位置、前置状态、操作、结果、持久化变化、视觉证据和测试编号。
- 双向核对：旧版每个可达行为必须有 Flutter 对应项；Flutter 每个用户可见行为也必须能在旧版找到依据。
- 建立固定时钟、时区、主题、屏幕尺寸和测试数据，包括空态、逾期、部分还款、一次性、已结清、Premium、错误态等。
- 建立截图、几何、文本、语义树、存储快照和交互轨迹差分工具，并验证工具能识别人为制造的差异。

完成门槛：零个“未分类入口”，所有条目都有源码锚点和测试方法。允许存在“已发现待修差异”，但不能还有未知范围。

## 阶段 8.2：计算、数据模型与持久化契约

完整关闭所有与 UI 无关的底层行为差异。

工作范围：

- 全量对账 JS 与 Dart 计算函数，不局限于现有十几个探针。
- 覆盖日期、四舍五入、计划生成、排序、部分还款、减免、结清/恢复、提前还款、报告数据和通知计划。
- 核对全部存储 key、JSON 形状、默认值、旧格式兼容、损坏数据降级和重启恢复。
- 修复已发现的备份 key、模拟器状态、已结清债务编辑字段等问题。
- 使用固定用例加固定 seed 随机差分，比较操作前后的完整数据快照。

完成门槛：底层 parity matrix 全部关闭；同一输入下数据、格式和持久化结果一致，重启后仍一致。

## 阶段 8.3：全局视觉系统、应用壳与通用交互

一次完成所有页面共享的视觉和交互基础，避免后续反复返工。

- 系统栏、安全区、页面宽度、底部导航、切页动画及切页后的滚动/手势状态复位。
- 登录门的视觉与动画外壳。
- 按钮、输入框、卡片、Toast、确认弹窗、三按钮弹窗、Popover、Picker、Sheet、Subpage 等公共组件。
- 全部入口的打开形态和关闭契约，包括编辑、详情、通知设置必须使用旧版对应的底部抽屉。
- 键盘避让、遮罩点击、系统返回、焦点、滚动、减少动画和无障碍语义。

完成门槛：公共组件和应用壳在明暗主题下零未解释差异；导航层级、返回键、键盘和遮罩行为均有回归测试。

## 每个阶段固定收尾流程

每个阶段必须完整执行：

1. 完成本阶段 parity matrix，且本阶段零遗留。
2. 运行相关差分/golden/widget/integration 测试、全量 `flutter analyze`、全量 `flutter test`、APK 构建和 `git diff --check`。
3. 检查未修改任何受保护旧版文件。
4. 更新阶段证据、对齐矩阵、`README.md`、`AGENTS.md` 和本机 `PROGRESS.md`，但不提前宣称整个阶段 8 完成。
5. 精确暂存文件，复核生成物和隐私数据，然后 `git commit`。
6. `git push origin main`，确认远端提交和 CI 全绿。
7. 向用户报告 commit SHA、测试结果、矩阵完成数量、证据位置和下一阶段前置条件。
8. 立即停止，等待用户明确审核通过；不得开始下一阶段。

任何测试、真机验证、外部配置、push 或 CI 没完成，都意味着该阶段仍在进行中，不能写成“完成但某项以后再测”。

现有决定是 iOS 暂缓，所以 agent 不会把 iOS 写成“已验证”。在 8.10 结束前需要明确选择：
