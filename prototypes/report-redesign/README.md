# After Zero 统计页 · 三套静态视觉原型

只用来看和比，**不参与任何构建流程**，跟 `www/` / `react/` / `android/` 完全隔离。
`npx cap sync android` 只拷 `www/`，这个目录不会进 APK；`npm test` 的 glob 锁死在
`test/*.test.js`，`vitest` 只看 `react/`，两套测试都扫不到这里。

## 怎么打开

**双击 `index.html` 就行**（`file://` 下能正常跑：`data.js` 是普通 `<script>`，没有用
ES module / fetch，三个 iframe 是同目录相对路径）。

想用本地服务器也可以：

```bash
cd prototypes/report-redesign
python3 -m http.server 8791
# 然后打开 http://localhost:8791/
```

- `index.html` —— 总览。三栏 390px iframe 并排，顶部一个开关同步切三套的深浅色，
  上方一条数据带列出这份数据的关键值。
- `a-native.html` / `b-narrative.html` / `c-minimal.html` —— 三套方案，可以单独打开。
  每页右上角有独立的深浅色切换按钮，选择存在 `localStorage["az-proto-theme"]`。
- 桌面打开时内容居中成 390px 手机框；窗口 ≤430px（真机）时自动铺满全屏。
  底部复刻了正式 App 的 tabbar，保证"页面底部有多少空间被占掉"跟真机一致。

## 数据从哪来

**不是编的。** `build-data.js` 构造 12 笔债务，喂给**真实的 `www/js/calc.js`**，把
`recompute` / `computeReportData` / `computeUpcomingPressure` / `summarizeDebts` /
`pressureWindowMonths` / `remainingInterest` 的输出烘焙成 `shared/data.js`，三套原型读同一份。

数据形状对齐 2026-07-31 那张真机统计页截图：

| | 截图 | 原型 |
|---|---|---|
| 在还总负债 | ¥58,988 | ¥58,988 |
| 银行贷 / 信用卡分期 / 网贷 | 61% ¥35,711 / 27% ¥16,208 / 12% ¥7,069 | 逐项相等 |
| 12 笔债务余额 | ¥25,000 … ¥461 | 逐笔相等 |

类型归属是**反推出来**的：三类合计必须分别等于 35,711 / 16,208 / 7,069，这个约束下
拆分唯一（银行贷 = test11+test8+test3，网贷 = test9+test2+test1+test10，其余归信用卡分期）。
其余数值（已还本金 ¥49,457、加权年化 10.84%、归零进度 46%、压力窗口 27 个月、
峰值 26年9月 ¥6,186、预计还清 2028-09-15）全部是 `calc.js` 真算出来的。

`build-data.js` 带自检：余额对不上目标、`amount ≠ principal+interest`、本金为负、
类型合计对不上截图，任意一条不过就 `exit 1` 不产出数据。重新生成：

```bash
node prototypes/report-redesign/build-data.js
```

## 三套的核心差异

| | A 原生延续 | B 债务洞察叙事 | C 极简数据产品 |
|---|---|---|---|
| 顶部 | 石墨渐变 hero + 色雾动效 + 归零进度条，36px 数字 | 报告头：日期 + 判断句标题，总额写进段落 | 无卡片，46px 巨号数字直接压在页面底色上 |
| 容器 | 5 张同构卡片（18px / `--card-grad` / `--e2` / 顶部内高光） | 五个语义段落，只有图表处有轻容器（`--e1`） | 零容器，只有 hairline + 34px 段间距 |
| 结论 | 固定 6 行 key-value 总结卡 | **规则驱动**：4 条候选结论按严重度排序取前 3，"最该先动手"取可行动里最高的那条展开 | 定义列表，高息相关行用琥珀 |
| 压力图 | 4 格摘要 + 27 个月柱状图 + 点击展开当月明细 | **面积 / 柱状两种模式可切换**（默认面积，不持久化），横向滑动 + 点月看明细、再点收起 | 柱高砍到 78px，2 条刻度线，读数在图上方 |
| 走势图 | 折线 + 面积渐变 + 3 个时间刻度 | 放大成主角，三个节点的**名称+时间+金额标在图上** + **按住拖动读任意时间点的余额**，不画坐标轴 | sparkline 级细线，只标首尾两个数字 |
| 排行 | 全部 12 笔 + 余额/利率/剩余利息三档切换 | **累计占比达 70% 为止**（当前 → 前 4 笔），其余折叠 | 全部 12 笔，无底槽实心条，高息用琥珀区分 |
| 类型占比 | 26px 堆叠条 + 胶囊图例 | **可拖拽旋转的甜甜圈**（r=76），标签贴容器边缘 + 折线引线，文字始终水平，无图例 | 4px 细线 + 三行文字 |
| 数据色 | 3 色角色制：蓝=量级 / 琥珀=成本 / 绿=进度 | 风险二档：红=年化≥18% / 蓝=其余 | 2 色：墨色 + 琥珀 |

三套都保留：本金/利息可区分（颜色 + 常驻图例 + 文字读数三重编码）、每个数值都有不靠
手势就能读到的路径、"预测不是承诺 / 本 App 不保存历史余额"的说明、走势图 X 轴按**真实
时间比例**而不是数组下标等距。图表容器一律不透明，没有毛玻璃。

A 还顺手修掉了审计里点名的三处不一致：图例从 2–3px 圆角方块改成 999px 胶囊（跟全局
`.tag` 统一）、⋮ 三点菜单换成具名"导出"按钮（那个符号全 App 只有统计页用）、
补回"债务"tab 有而统计页没有的 hero 色雾层。

### B 的结论规则引擎（第二轮改动的核心）

原来"三件值得注意的事"是写死的三句话+插值数字，其中一句在这份数据下**是假的**：
"4 笔网贷吃掉了大部分利息"——实测网贷占余额 12.0%、占剩余待付利息 12.9%，几乎等比例，
根本谈不上"大部分"。真正吃利息的是 test11（银行贷，年化才 5.79%）一笔占 41%，
因为它金额大、期限长。**高利率 ≠ 高剩余利息，这两件事必须分开算。**

现在是 4 条候选结论，各带触发条件和严重度公式（源码里逐条写了理由）：

| 结论 | 触发条件 | severity 公式 | 可行动 | 当前数据 |
|---|---|---|---|---|
| 利息集中度 | 单笔占剩余待付利息 ≥30% | 该占比 × 100 | ✓ | 41（test11 占 41%） |
| 高息债务 | 存在年化 ≥18% | 余额占比×100 + (最高年化−18)×2 | ✓ | 35 |
| 还款峰值月 | 峰值 ÷ 月均 ≥ 1.5 | (倍数−1)×60，封顶 100 | ✓ | 100（2.66 倍） |
| 利息负担分档 | 恒成立 | 轻 10 / 中 45 / 重 80 | ✗ | 10（6.6%，最轻档） |

- "三件值得注意的事" = 按 severity 取前 3（不限可行动）
- "最该先动手的地方" = **可行动**里 severity 最高的那条展开，展开内容由那条结论自己提供
  （峰值月 → 那个月同时到期的债务清单；高息 → 高息债务利率条；利息集中 → 按剩余利息排序）
- 高息那条的类型名（"网贷"）也是算出来的：只有这批债务恰好同类型时才提类型名，否则说"债务"

### B 的两处交互决定

**走势图不画坐标轴**（这是判断，不是漏了）：三个里程碑已经把"起点多少、中点什么时候、
终点归零"三个锚点写在图上了，再画 Y 轴刻度和 X 轴时间刻度等于同一份信息写两遍，
而且刻度数字会跟里程碑标签抢位置。精确值改由**按住拖动**承担——图上方一行显示落点的
日期和余额，拖动时里程碑淡到 0.18 避免两套标签打架。这是 A 方案 PayoffLine 已经验证过的
scrub 交互。触摸走 Touch Events + `{passive:false}`，且先判方向（横向为主才接管，
纵向让给页面滚动）。

**压力图保留两种图形**：默认堆叠面积（回答"整体压力曲线什么形状"），可切到柱状
（回答"逐月分别是多少"）。模式存内存不持久化，重开 App 回到面积。
切换时**保留当前选中的月份**——换个画法看同一个月，不该把选择清掉。

两种模式都标峰值，但实现不同：柱状靠 `.pcol.peak::after` 挂在"那根柱子"这个元素上；
面积图没有对应的 DOM（只有两条连续 `<path>`），所以按峰值点坐标单独定位一个 `.apeak`
（x 用跟 SVG 采样点/命中格子同一套的 `(i+0.5)/n`，y 用 total 线的高度），下面接一个朝下
的小三角指回顶点。**面积图比柱状更需要这个标注**——连续曲线会把局部起伏平滑掉，
肉眼挑不出最高点。选中的正好是峰值月时，标注淡到 0.3 让位给读数竖线+圆点。

**切换模式时卡片尺寸和坐标轴必须纹丝不动**：给"峰值"标注留的头顶空间放在两种模式
共用的 `.pcanvas`（18px），不是只给柱状加（上一版就是这么错的，切到柱状卡片整体拉长
14px、刻度线跟着跳）。也**不能直接给 `.achart`/`.pbars` 加 padding**——`.achart` 里有
绝对定位的游标竖线和圆点，它们的 `inset`/`bottom` 百分比是相对 **padding box** 算的，
一加 padding 整套坐标就偏。有断言逐项比对切换前后的卡片高度、三条刻度线、x 轴的相对偏移
（都必须 0 差异）。

## 配色验证记录

全部跑 `dataviz` skill 的 `scripts/validate_palette.js`，浅深各验一次，`--pairs all`。

| 方案 | 模式 | 色值 | 结果 |
|---|---|---|---|
| A | 浅 | `#2B6CB8` 蓝 / `#C4892F` 琥珀 / `#068468` 绿 | **ALL PASS**（最差对 normal ΔE 16.4） |
| A | 深 | `#5590D8` / `#BC8B3C` / `#43A883` | **ALL PASS**（最差对 normal ΔE 15.6） |
| B | 浅 | `#C42F2F` 红 / `#2F639C` 蓝 | **ALL PASS**（normal ΔE 27.5，protan 16.8） |
| B | 深 | `#DC6767` / `#5E96D0` | **ALL PASS**（normal ΔE 23.1，protan 15.8） |
| C | 浅 | `#242E3D` 墨 / `#C4892F` 琥珀 | 分离度 normal ΔE 40.6 / protan 36.5；**lightness band 与 chroma floor 两项刻意 FAIL，见下** |
| C | 深 | `#D6DCE6` / `#BC8B3C` | 同上，normal ΔE 25.7 |

### C 的两项 FAIL 是有依据的偏离，不是漏跑

墨色 `#242E3D` 的 chroma 是 0.031，验证器判"reads gray"。但 C 的设计前提就是**不靠色相
区分身份、靠明度区分**——chroma floor 和 lightness band 这两项检查是给"色相承载身份"的
分类色板设的，在这里前提不成立。真正决定"能不能分辨"的两项（normal-vision ΔE 与 CVD ΔE）
是三套里最高的。记在这里是为了让偏离可追溯，不是拿它当免检理由。

### 验证过程中发现的两个正式 App 现存问题

**① 我上一轮给正式 App 换的折线/横条配色，两个颜色之间分不开。**
把 `--ch-line` 改成蓝 `#2D63C8`、`--ch-bar` 改成紫 `#7451B8` 时，我只验了每个颜色**单独
对底色**的对比度（都过），没验**这两个颜色之间**的分离度。补验的结果：

```
#7451B8 ↔ #2D63C8   normal ΔE 9.8（低于 15 的硬性下限）· protan ΔE 3.4
```

也就是"每张图一个色相"这个目标只做到一半——蓝和紫在正常视觉下就已经很接近，红绿色盲
下基本是同一个颜色。这正是 `AGENTS.md` 里记过的那条教训（"只验色 vs 背景会漏掉相邻
那一对"）的再次复现，只是这次相邻的两个色分处不同图表，更容易被忽略。三套原型都没有
沿用这个组合。

**② App 现有的三档利率标签色（`.tag.rate-hi/mid/lo`）红↔琥珀分不开。**
B 方案本来打算按现有语义色做三档风险（红 `#BE3A3A` / 琥珀 `#A66A0A` / 蓝 `#2E5F8A`），验证结果：

```
#A66A0A ↔ #BE3A3A   normal ΔE 12.4（低于 15）· deutan ΔE 4.5
```

试过把琥珀往橙黄推，红↔橙的 normal ΔE 最高只能到 13.5，再往亮推就跌破 3:1 对比度——
**红/橙/蓝这个三档配色在色相上就不成立**。所以 B 改成二档（红=高息 / 蓝=其余）并且每行
直接写着利率数字，颜色不是唯一编码。这条对正式 App 同样适用：那三个标签色现在是靠
标签上的文字（"18.5%"）在扛区分，不是靠颜色。

## 验证过什么

Playwright headless，390×844，浅深两套主题各跑一遍：

- 三套页面 + 总览页，**零 JS 报错、零横向溢出**（`scrollWidth === clientWidth`，量出来的不是眼看的）
- 交互都跑过：A 的三档排序切换 / 口径说明折叠 / 点柱子看当月明细；B 的"其余 9 笔"展开 /
  点柱子看本金利息构成；C 的点柱子切月份。交互后重新检查横向溢出，仍然是 0
- 总览页切深浅色能同步三个 iframe（`postMessage`，iframe 是独立文档，改父页面的
  `data-theme` 传不下去）

修掉的问题（都是截图里看出来的，不是推测）：

**第一轮**

1. **B 的一句文案是假的**——"是放在 28.49% 的低息债务上的 5.9 倍"，28.49% 那笔本身就是
   高息（阈值 18%），而 5.9 这个倍数是拿另一笔 5.01% 的债务算的，名字和数字来自两笔不同
   的债务。改成同一笔（利率最低的 test3，5.01%）。
2. **C 的压力图为了高亮选中月，把其余月份调到 opacity .3**，结果整张图只剩一根柱子能读。
   改成所有柱子一律实色，选中态只体现在 x 轴刻度加粗 + 柱底一条 2px 标记。
3. **C 的类型占比第三档用了 `--ink-dim`**（14% 透明度的墨色），在图例里几乎看不见
   （浅色下对白底只有 1.1:1）。改用 `--text-muted`，两套主题下都在 4:1 以上。

**第二轮（B 改版时）**

4. **`fill: var(--card-grad)` 在 SVG 里无效，浏览器回退成黑色**——饼图的中心孔和扇区描边
   原来写的是这个（`--card-grad` 是 `linear-gradient(...)`），SVG 的 `fill`/`stroke`
   不接受 CSS 渐变值，浅色模式下中心孔和描边全是黑的。改成纯色 `var(--surface)`。
   **这条对正式 App 也适用**：以后往 SVG 上写颜色，只能用纯色 token，不能用
   `--card-grad`/`--app-grad` 这两个渐变。
5. **还清进度图的三个标签第一版按"哪边空放哪边"排**，结果起点和中点的标签 top 只差 7px、
   横向只隔 30%，读起来像连成一行的一句话。改成按纵向错开排（上 / 中下 / 中上，至少差 60px）。
6. **饼图引线用 `--hair` 等于隐形**（深色下是 `rgba(255,255,255,.07)`，1px 线在卡片底上
   看不见）。改用 `--border`。
7. **明细列表里金额小数位不齐**（"¥1,089" 和 "¥666.16" 混排）。共享的 `fmt()` 沿用 App 行为
   （≥1000 取整、<1000 保留两位），headline 继续用它；明细列表改用 `yuan()` 先取整到元。

**第三轮（B 加交互时）**

8. **`overflow-x: auto` 会连带把 `overflow-y` 变成非 visible**——柱状模式里"峰值"标注画在
   `top:-14px`（柱子容器外），被外层横向滚动容器整个裁掉，9 月那根柱子上方什么都没有。
   修法是把绘图区整体下移 14px（`.pbars` 加 `padding-top` + `content-box`），刻度线层
   `.agrid` 跟着下移同样距离才对得上。**这条对正式 App 的 `PressureChart.tsx` 同样适用**：
   那个组件的 `.pchart-peak` 三角标记在 `top:-1px`，只差 1px 没被裁到，往外挪一点就会中招。
9. **饼图半径卡在标签宽度上**。第一版标签"沿半径方向直着往外放"，扇区转到正左/正右时
   水平空间只剩 60 多 px，`r` 只能给到 62。改成**贴容器边缘 + 折线引线**后水平空间跟角度
   无关；再按 Playwright **实测**的标签宽度（70.5px，中文实际渲染比按字号×字数估的窄不少）
   反推出 `r=76`，比第一版大 23%，且留 7.5px 间隙。有回归检查盯着"标签不压到饼上"这条。
10. **`ElementHandle` 在 `render()` 重建 innerHTML 后会失效**（写验证脚本时踩的）。
    这个原型是"改 state → 整段 innerHTML 重渲染"的模式，测试里存下来的 handle 点第二次就
    报 `Element is not attached to the DOM`，必须每次重新按选择器查。

**第四轮（用户从截图里指出来的）**

11. **`display:inline` 会静默忽略 `width`/`height`**——"最该先动手"里那 6 根条形的
    `.fill` 是 `<span>`，内联样式 `width:100%/68.9%/…` 全都算对了却完全不生效，
    实测 `getBoundingClientRect()` 宽高都是 **0**，界面上只剩空的灰色底槽：
    条形长度差异（¥1,089 vs ¥540 该差一倍）和琥珀色一起消失。
    `.track` 因为有 `flex:1` 被 flex 容器 blockify 了所以尺寸正常，`.fill` 在它里面
    没人 blockify，必须自己声明 `display:block`。
    **这类问题肉眼很难在整页截图里发现**（6px 高的条），所以补了一条全局扫描断言：
    遍历所有元素，凡是"内联样式设了 width/height 但 computed display 是 inline"的
    一律报错，三套原型 + 两种图表模式 + 展开态都扫。
12. **文案说 11 笔却只列 6 笔**——`slice(0, 6)` 截断了，但正文写的是
    "这个月一共有 11 笔债务同时到期："，冒号暗示"就这些"，另外 5 笔和它们的 ¥2,019
    凭空消失。这是在骗读者不是省略。改成"…一共有 11 笔债务同时到期，金额最大的 6 笔是："
    并在列表末尾补一行"其余 5 笔 · ¥2,019"，6 行金额 + 其余合计 = 峰值月总额 ¥6,186，
